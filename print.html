Stage Manager for Windows

Introduction

Stage Manager for Windows brings the visual, stage-based multitasking interface of macOS to Windows 10 and 11 as a high-performance native Rust application.

Unlike screenshot-polling utilities or heavy web-based shells, Stage Manager links directly into the Windows Desktop Window Manager (DWM) hardware compositor and uses second-order damped spring physics paced to the display’s vertical blank (DwmFlush) for fluid 60Hz and 120Hz high-refresh animations.

Why Stage Manager for Windows?

Traditional Windows multitasking relies on crowded taskbars and flat Alt + Tab grids that can quickly become cluttered when working with multiple projects or browser tabs. Stage Manager re-imagines your desktop as a collection of focused Stages:

  • Fewer Distractions: Your active work stays centered on the screen, while inactive workspaces float quietly on the side.
  • Hardware-Accelerated Compositing: Previews are rendered directly by the GPU compositor (DwmRegisterThumbnail) — zero CPU screenshot polling.
  • Sub-Megabyte Footprint: Compiles to a self-contained ~540 KB executable using under 20 MB of system RAM.
  • True Multi-Screen Isolation: Each connected monitor manages its own independent stage strip, trigger sensor, and DPI scaling.

Getting Started

This guide walks you through installing and launching Stage Manager for Windows.

System Requirements

  • Operating System: Windows 10 version 20H1 (build 19041) or higher, or Windows 11
  • Architecture: x64 (64-bit Intel or AMD processor)
  • Desktop Window Manager: Enabled (default on all modern Windows installations)
  • Administrative Privileges: Not required (installs and runs in user space)

Installation Options

Option 1: Standalone Installer (StageManagerSetup.exe)

  1. Download StageManagerSetup.exe from the GitHub Releases page.
  2. Double-click the installer:
    • Installs to %LOCALAPPDATA%\StageManager\stage_manager.exe
    • Creates a Start Menu shortcut (Stage Manager)
    • Registers in Windows Settings → Apps → Installed Apps
    • Automatically enables Run at Windows Startup
    • Launches Stage Manager directly into the notification tray
  3. Unattended silent install: 
    .\StageManagerSetup.exe --silent

Option 2: Clone from GitHub & Build (Recommended for Developers)

# 1. Install Git and Rust (if not already installed)
winget install --id Git.Git -e --source winget; winget install --id Rustlang.Rustup -e --source winget

# 2. Clone repository
git clone https://github.com/fruitsaladwindowsai-zammy/Stage-manager-Rust.git
cd "Stage-manager-Rust"

# 3. Run immediately
cargo run --release

Option 3: Portable Mode (Zero-Install)

  1. Download stage_manager.exe from Releases.
  2. Place it in any directory (e.g. C:\Tools\stage_manager.exe).
  3. Double-click to run. Runs entirely in your notification tray without modifying the Windows registry.

Verifying It’s Running

Look at the bottom-right corner of your taskbar next to the clock. You should see the Stage Manager squircle icon.

  • Move your mouse cursor to the left edge of your monitor to reveal the Stage Manager strip.
  • Click any stage card to bring that application to the front!

Stage Mechanics & Group Fan-Out

Stage Manager organizes your applications into fluid stages with automatic grouping and horizontal fan-out.

1. What is a Stage?

  • A Stage represents an active workspace containing one or more related application windows.
  • Inactive stages float in an auto-hiding ribbon on the side of your display, showing live hardware thumbnails.
  • Clicking an inactive stage seamlessly swaps it into focus while retracting the previously active stage back onto the strip.

2. Multi-Window Grouping & Fan-Out

When grouping_mode = ByApplication:

  • All windows belonging to the same executable (e.g. multiple Chrome tabs or VS Code editors) are clustered into one stage.
  • Up to 5 cascaded preview thumbnails are stacked with depth offsets.
  • Horizontal Fan-Out: Hovering over the card fans out the windows horizontally with individual squircle icons. Clicking any specific window brings that window directly to the front.

3. Dynamic Merging & Splitting

  • Merge: Hold Shift and left-click an inactive stage card. It will immediately join your current active stage rather than replacing it.
  • Separate: Drag any window titlebar away from the grouped layout, and Stage Manager will split it back into an independent stage.

Physics & 120Hz Dynamics

Every visual movement in Stage Manager is calculated using second-order damped spring equations synchronized with the hardware vertical blank.

1. Damped Spring Equations

Unlike fixed linear or bezier easing curves, damped springs adapt naturally to user interaction:

$$\frac{d^2 x}{dt^2} + 2\zeta\omega_n \frac{dx}{dt} + \omega_n^2 (x - x_{\text{target}}) = 0$$

  • Stiffness ($k = 240.0$): Governs how quickly cards accelerate toward target coordinates.
  • Damping ($c = 26.0$): Controls how gently movement settles, preventing unnatural overshoot.

If you suddenly change cursor direction mid-flight, the spring dynamically redirects without stuttering or snapping.

2. Inward Curved Ribbon Wave

When you hover over a stage card:

  1. The hovered card pops forward toward you (+12px scale and subtle illumination glow).
  2. The neighboring cards immediately above and below curve inward toward the screen bezel: $$\Delta x_i = -A \cdot \exp\left(-\frac{(y_i - y_{\text{cursor}})^2}{2\sigma^2}\right)$$
  3. As the cursor glides vertically, the wave rolls along the stage ribbon smoothly.

3. VSync Synchronization via DwmFlush

The animation loop calls DwmFlush() on a background thread:

  • DwmFlush() blocks until the Windows DWM compositor performs a vertical blank.
  • This ensures frame calculations align with 60Hz, 120Hz, or 144Hz display refresh rates.
  • When springs settle to target coordinates, the animation thread transitions to an idle state, consuming 0% CPU.

Multi-Monitor & Extended Displays

Stage Manager treats every display and virtual desktop as an independent, isolated multitasking workspace.

1. Per-Monitor Strip Isolation

Unlike taskbars that mirror or duplicate cards across screens, Stage Manager implements true Per-Monitor Isolation:

  • Each connected monitor runs its own independent Sidebar window and trigger zone.
  • Windows positioned on Monitor 1 are managed exclusively on Monitor 1’s stage strip.
  • Windows positioned on Monitor 2 are managed exclusively on Monitor 2’s stage strip.
  • Moving an application window from Monitor 1 to Monitor 2 automatically migrates its stage card across to the destination monitor.

2. Multi-Monitor Span Mode & Boundary Isolation

In multi-monitor setups where Windows displays are placed side-by-side or when the desktop wallpaper is configured in Span mode, virtual desktop coordinates are continuous:

  • Stage Manager preview windows, the Acrylic backdrop blur, and the Direct2D icon overlay are clamped strictly to self.work_area.
  • When the sidebar slides off-screen or reveals, cards utilize horizontal normalized cropping (clip_left_frac and clip_right_frac) in addition to vertical bounds cropping.
  • Elements sliding off the screen edge smoothly crop against the monitor boundary and never bleed into or split across adjacent displays.

3. Display Hotplugging

When displays are connected, disconnected, or reconfigured:

  1. Windows emits WM_DISPLAYCHANGE.
  2. Stage Manager re-enumerates displays via EnumDisplayMonitors.
  3. New monitors spawn independent sidebars; disconnected sidebars are torn down gracefully.
  4. Window associations are retained without crashing.

3. Windows Virtual Desktops

Stage Manager integrates with the Windows 10 & 11 IVirtualDesktopManager COM interface:

  • Windows are tagged with their owning Virtual Desktop GUID via GetWindowDesktopId.
  • Switching desktops (Win + Ctrl + Left/Right) swaps the active stage collection immediately.
  • A clean virtual desktop provides a clean stage ribbon with zero window bleed from prior desktops.

Administrator & Elevated Applications

This guide explains how Stage Manager interacts with elevated (Administrator) windows under Windows User Account Control (UAC).

1. User Interface Privilege Isolation (UIPI)

Windows enforces UIPI (User Interface Privilege Isolation):

  • A non-elevated (standard user) process cannot send certain window messages (WM_COMMAND, WM_SYSCOMMAND) or manipulate windows owned by an elevated (Administrator) process.
  • Stage Manager runs as standard user by default, requiring zero administrator privileges to install, configure, or run.

2. Managing Elevated Windows

When an application runs with elevated privileges (e.g. an Administrator Command Prompt or PowerShell):

  • Stage Manager can still display live DWM thumbnails and track window boundaries.
  • However, bringing an elevated window to the front or switching focus via Win32 SetForegroundWindow may be restricted by Windows security policies.

3. Running Stage Manager Elevated (Optional)

If your daily workflow involves managing numerous elevated development tools or administrative terminals, you can optionally run Stage Manager as Administrator:

  1. Right-click stage_manager.exe (or your Start Menu shortcut).
  2. Select Run as administrator.
  3. Stage Manager will now possess matching integrity level to manage all elevated windows without restriction.

Configuration Reference

Stage Manager for Windows provides fine-grained control over positioning, sensitivity, visual glass styling, and grouping mechanics.

1. System Tray Configuration

Right-clicking the Stage Manager squircle icon in your Windows system tray exposes the runtime configuration menu:

  • Side Edge: Dock the sidebar to the Left or Right screen boundary.
  • Trigger Mode:
    • Full Edge (Default): Trigger anywhere along the active screen edge.
    • Top Corner: Trigger via an 18×18px sensor at the top-left or top-right corner.
    • Bottom Corner: Trigger via an 18×18px sensor at the bottom-left or bottom-right corner.
  • Backdrop Blur Strip: Toggle translucent frosted backdrop behind floating cards.
  • Glass Theme:
    • Dark Frosted: Deep translucent dark glass (rgba(18, 18, 24, 0.72)).
    • Light Frosted: Bright translucent glass (rgba(245, 245, 250, 0.78)).
    • Acrylic: Windows 11 Acrylic material blur (DWMWA_SYSTEMBACKDROP_TYPE = 3).
    • Mica: Windows 11 Mica surface material blur (DWMWA_SYSTEMBACKDROP_TYPE = 2).
  • Grouping: Switch between By Application (cascaded stacks with hover fan-out) and Single Window (standalone cards).
  • Run at Windows Startup: Automatically launch on Windows boot via user registry key.

2. Windows Startup Registry

Stage Manager manages startup cleanly in the current user’s registry hive without requiring administrator privileges:

HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run\StageManager

Value: "C:\Users\<Username>\AppData\Local\StageManager\stage_manager.exe"

Architecture & Internals

Stage Manager for Windows is built with clean, safe Rust on top of the native Windows 10 & 11 Win32 and Desktop Window Manager (DWM) APIs.

1. High-Level Subsystems

src/
├── main.rs            # Entry point: DPI awareness, COM initialization, single-instance mutex
├── app.rs             # Multi-monitor coordinator, WinEvent dispatch, workspace routing
├── window_tracker.rs  # Window enumeration, filtering, WinEvent hook lifecycle
├── desktop.rs         # Monitor enumeration, IVirtualDesktopManager COM interop, startup registry
├── stage_manager.rs   # Stage data structures, grouping logic, stage-switching state
├── sidebar.rs         # Per-monitor floating strip window, hover sensors, layout coordination
├── layout.rs          # Pure geometric layout calculations, fan-out positions, hit testing
├── renderer.rs        # Direct2D vector rendering, squircle badge drawing, UpdateLayeredWindow
├── thumbnail.rs       # DwmRegisterThumbnail and DwmUpdateThumbnailProperties wrapper
├── animation.rs       # Damped spring physics engine, FrameClock, VSync synchronization
├── blur.rs            # Windows 11 Acrylic & Mica DWM window attribute helpers
├── hotkeys.rs         # RegisterHotKey bindings with fallback handling
├── tray.rs            # Shell_NotifyIconW, right-click context menu, custom HICON creation
└── bin/setup.rs       # Standalone Windows installer and uninstaller

2. Event-Driven Lifecycle

Stage Manager avoids CPU-heavy polling loops by responding strictly to Windows OS events:

  1. WinEvent Hooks (SetWinEventHook): EVENT_SYSTEM_FOREGROUND, EVENT_OBJECT_LOCATIONCHANGE, EVENT_SYSTEM_MINIMIZESTART/END.
  2. Low-Level Pointer Sensor (WH_MOUSE_LL): Monitors cursor coordinates along the active monitor edge to trigger the auto-hide reveal spring.
  3. Display Changes (WM_DISPLAYCHANGE): Re-enumerates monitors upon display hotplug.
  4. Shell Notifications (WM_TASKBARCREATED): Re-registers the system tray icon automatically if Windows Explorer crashes or restarts.

3. Direct2D Layered Window Compositing

Window badges, squircle process icons, and active hover glow highlights are drawn onto a transparent layered window (WS_EX_LAYERED | WS_EX_TRANSPARENT) positioned directly over the thumbnail strip, blitted via UpdateLayeredWindow with 32-bit ARGB alpha blending.

Building from Source

This guide covers building Stage Manager from source code on Windows 10 or 11.

1. Prerequisites

  • Windows 10 version 20H1+ or Windows 11
  • Rust Toolchain (stable): Works with either x86_64-pc-windows-gnu or x86_64-pc-windows-msvc
  • Git for Windows
winget install --id Git.Git -e --source winget; winget install --id Rustlang.Rustup -e --source winget

2. Compiling the Main Executable

# Clone repository
git clone https://github.com/fruitsaladwindowsai-zammy/Stage-manager-Rust.git

# Development build
cargo build

# Release build
cargo build --release --bin stage_manager

cargo test

Contributing Guide

Thank you for your interest in contributing to Stage Manager for Windows!

1. Development Workflow

  1. Fork & Branch: Create a feature branch from master: 
    git checkout -b feature/my-cool-feature
  2. Coding Standards:
    • Run cargo fmt before committing.
    • Ensure cargo clippy --all-targets -- -D warnings produces zero warnings.
    • Run cargo test to verify all 12 tests pass.
  3. Submitting a Pull Request:
    • Open a PR against master.
    • Describe what changed and include screenshots or GIFs for visual changes.

2. Safety Guidelines

  • Stage Manager maintains safe Rust practices across the codebase.
  • Any Win32 API calls must be wrapped cleanly inside unsafe blocks with clear invariants.
  • Ensure GDI handles (HICON, HBITMAP, HDC) and COM objects are cleaned up properly to prevent resource leaks.
